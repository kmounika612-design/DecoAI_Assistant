# SD3 Local NPU Image Generation

A local text-to-image inference toolkit for **Stable Diffusion 3 Medium**, accelerated on a
Qualcomm Snapdragon NPU via ONNX Runtime QNN execution provider. Local-only: no cloud backend,
no hybrid orchestrator. 

Verified working end-to-end on this device (Snapdragon X Elite, QAIRT SDK 2.43.0) — a 512×512
image generates in ~8s.

---

## Architecture

```
bin_to_onnx.py            (one-time setup: convert serialized context binaries -> onnx)
    └── gen_qnn_ctx_onnx_model.py

SD3_Tool.py                (per-generation client)
└── session_server.py      (persistent, keeps 4 sessions warm)
    └── ONNX Runtime + QNN HTP
```

### Components

| File | Purpose |
|---|---|
| `bin_to_onnx.py` | One-time setup — converts the 4 `*.serialized.bin` context binaries into `Model_Bins/*.onnx` |
| `gen_qnn_ctx_onnx_model.py` | Microsoft's ORT-QNN wrapper generator (called by `bin_to_onnx.py`) |
| `session_server.py` | Persistent ONNX session server — keeps all 4 models warm in memory |
| `SD3_Tool.py` | Local SD3 inference client — tokenizes, encodes, denoises, decodes |
| `requirements.txt` | Python dependencies |
| `SKILL.md` | Agent skill definition for Claude Code integration |
| `serialized_binaries/` | Source QNN context binaries + model config manifests (input to `bin_to_onnx.py`) |

## Requirements

### Hardware
- Qualcomm Snapdragon SoC with HTP (NPU) support (tested on Snapdragon X Elite)
- Windows 11 (required for `QnnHtp.dll` and related QNN DLLs)

### QAIRT SDK

The pip-installed `onnxruntime-qnn` package bundles its own (older) `QnnHtp.dll`, which **cannot
load context binaries built by a newer QAIRT SDK** — loading fails with
`QNN_CONTEXT_ERROR_INVALID_ARGUMENT` (error 5000). Both `bin_to_onnx.py` and `session_server.py`
instead point at a full QAIRT SDK install matching the version the binaries in
`serialized_binaries/` were built with (2.43.0 here):

```python
QAIRT_SDK_ROOT = r"C:\Users\HCKTest\Downloads\qairt-sdk-v2.43.0.260128150333_193827\qairt\2.43.0.260128"
```

If you move the SDK or use a different version, update `QAIRT_SDK_ROOT` at the top of both
`bin_to_onnx.py` and `session_server.py`.

### Model files

`Model_Bins/` is generated by `bin_to_onnx.py` (see [Setup](#setup) below) — you don't create it
by hand. Once generated it contains exactly 4 files:

```
Model_Bins/
├── text_encoder_qnn_ctx_fp32_io.onnx
├── text_encoder_2_qnn_ctx_fp32_io.onnx
├── transformer_qnn_ctx_fp32_io.onnx
└── vae_decoder_qnn_ctx_fp32_io.onnx
```

There is no `text_encoder_3` (T5-XXL) and no separate time-embedding checkpoint in this export —
see [Pipeline walkthrough](#pipeline-walkthrough) for why.

### Python dependencies

```bash
pip install -r requirements.txt
```

Key packages: `diffusers`, `transformers`, `torch`, `onnxruntime-qnn`, `onnx`, `pillow`, `numpy`

## Setup

### 1. Convert the context binaries to ONNX (one-time)

Source binaries live in `serialized_binaries/serialized_binaries/*.serialized.bin`. Convert them:

```bash
python bin_to_onnx.py
```

For each binary this:
1. Runs `qnn-context-binary-utility.exe` (from the QAIRT SDK) to extract its graph I/O metadata
   into `qnn_ctx_json/<name>.json`
2. Runs `gen_qnn_ctx_onnx_model.py` to wrap the binary in an ORT-QNN `EPContext` ONNX model,
   written to `Model_Bins/<name>_qnn_ctx_fp32_io.onnx`

`gen_qnn_ctx_onnx_model.py` here has two fixes over Microsoft's original script (both required
for this to work at all with current `onnx`/`onnxruntime-qnn` versions):
- `parse_qnn_graph()` now copies `tensor_info["id"]` into `QnnTensorStruct.id` — the original
  left it `None`, which crashes `sorted(..., key=lambda x: x.id)` in `generate_wrapper_onnx_file()`
- `helper.make_model()` now pins `ir_version=10` and opset `("", 22)` / `("com.microsoft", 1)` —
  without this, `onnx`'s installed defaults (IR 13, opset 26) produce a model
  `onnxruntime-qnn` 1.21.0 refuses to load

The transformer binary is ~2 GB, so this step takes a few minutes.

### 2. Start the session server

```bash
python session_server.py
# Optional: specify a custom model directory
python session_server.py --model_dir C:\path\to\Model_Bins
```

Leave this process running in the background. It listens on `127.0.0.1:50001` — a different
port from `sd3.5_ort_qnn`'s session server (`50000`), so both can run at the same time on one
machine without colliding.

If you see `OSError: [WinError 10048] Only one usage of each socket address...`, a previous
server instance is still holding the port. Find and stop it first:
```powershell
Get-NetTCPConnection -LocalPort 50001 | Select-Object OwningProcess
Stop-Process -Id <pid> -Force
```

### 3. Generate an image

```bash
python SD3_Tool.py --prompt "your image description"
```

```bash
python SD3_Tool.py --prompt "a red panda at sunset" \
    --negative_prompt "blurry, low quality"
```

Requires the session server to be running. Output is saved to
`C:\Users\HCKTest\.openclaw\workspace\Output\images\sd3_npu_output_<timestamp>.png`.

| Argument | Flag | Default |
|---|---|---|
| Prompt | `--prompt` / `-p` | required |
| Negative prompt | `--negative_prompt` / `-np` | generic quality/composition guard |

## SD3_Tool.py — deep dive

`SD3_Tool.py` is the local inference client for Stable Diffusion 3 Medium. It implements the
complete text-to-image pipeline on-device, offloading all neural network inference to the QNN
HTP (NPU) via the persistent session server.

### Configuration constants

```python
user_step            = 28       # denoising steps
tokenizer_max_length = 77       # CLIP token sequence length
height, width        = 512, 512
user_seed            = np.int64(3)
user_text_guidance   = 7.0      # classifier-free guidance scale
```

`user_step`/`user_text_guidance` come from `serialized_binaries/model_configs/diffuser.json`'s
`num-inference-steps`/`guidance-scale` — the calibration values for this exported QNN graph.
`height`/`width` are fixed by the exported `vae_decoder` graph's output shape
(`output_sample_dq [1, 512, 512, 3]`), not a configurable choice.

### Pipeline walkthrough

This pipeline differs from `sd3.5_ort_qnn`'s in three ways, all discovered by inspecting the
actual converted ONNX graphs' input/output tensors rather than assuming the 3.5 architecture:

- **No T5 (`text_encoder_3`)** — this export only has CLIP-L and CLIP-bigG encoders. The
  transformer's `encoder_hidden_states` input still reserves the T5 slot (77 sequence positions),
  which is zero-filled instead of real T5 output — the same behavior `diffusers`' SD3 pipeline
  uses when `text_encoder_3=None`.
- **No separate time-embedding checkpoint** — the transformer graph takes the raw scalar
  `timestep` directly as an input (`timestep_dq`); the time-embedding math is baked into the QNN
  graph itself, so no `CombinedTimestepTextProjEmbeddings` module or `.pt` checkpoint is needed.
- **No batch_size=2 support** — the transformer graph's inputs are fixed at batch size 1, so
  unconditional and conditional passes run as two separate calls per denoising step (rather than
  one batched call).

#### 1. Scheduler setup
A `FlowMatchEulerDiscreteScheduler` (`num_train_timesteps=1000`, `shift=3.0`) produces 28
evenly-spaced timesteps. SD3 uses Flow Matching rather than DDPM/DDIM, so the scheduler maps
noise predictions to denoised latents using an Euler ODE solver.

#### 2. Tokenizers
Two tokenizers are loaded — both plain `CLIPTokenizer`, loaded from the `tokenizer`/`tokenizer_2`
subfolders of the `stabilityai/stable-diffusion-3.5-medium` repo (using the default HF cache, so
an already-cached local snapshot is reused offline rather than requiring a fresh download of the
standalone `openai/clip-vit-large-patch14` / `laion/CLIP-ViT-bigG-14-laion2B-39B-b160k` repos):

| Tokenizer | Subfolder | Role |
|---|---|---|
| `tokenizer1` | `tokenizer` | CLIP text encoder 1 (CLIP-L) |
| `tokenizer2` | `tokenizer_2` | CLIP text encoder 2 (CLIP-bigG) |

Both the positive prompt and negative prompt are tokenized by both. Each sequence is
padded/truncated to length 77 and returned as `int32 [1, 77]`.

#### 3. Text encoders (via ONNX QNN)
Each tokenized sequence is passed to the session server for inference:

- `text_encoder` — CLIP-L. Returns `hidden_states [1, 77, 768]` and `text_embeds [1, 768]` (pooled).
- `text_encoder_2` — CLIP-bigG. Returns `hidden_states [1, 77, 1280]` and `text_embeds [1, 1280]`.

#### 4. Embedding assembly
CLIP hidden states from both encoders are concatenated along the feature dimension and
zero-padded to width 4096. A zero-filled T5 slot and additional zero padding bring the sequence
to length 160 — matching the transformer's `encoder_hidden_states_dq [1, 160, 4096]` input:

```
[CLIP-1 hidden (77, 768) | CLIP-2 hidden (77, 1280) | zero pad -> (77, 4096)]
[T5 slot, zero-filled (77, 4096)                                            ]
[zero padding (6, 4096)                                                     ]
```

Pooled CLIP embeddings from both encoders are concatenated to form a `[1, 2048]`
`pooled_projections` vector — fed directly to the transformer (no time-embedding module).

#### 5. Denoising loop
```
for i, t in enumerate(timesteps):          # 28 iterations
    uncond_noise = run_transformer(pooled_uncond, uncond_embed, latent_in, [t])
    cond_noise   = run_transformer(pooled_cond,   cond_embed,   latent_in, [t])
    latent_in    = run_scheduler(...)       # Euler step
```

CFG (Classifier-Free Guidance) merges the two noise predictions:
```
noise_pred = uncond + guidance_scale × (cond − uncond)
```

The transformer's real ONNX inputs are `pooled_projections_dq [1,2048]`,
`encoder_hidden_states_dq [1,160,4096]`, `hidden_states_dq [1,64,64,16]` (NHWC latent), and
`timestep_dq [1]` (raw scalar). Its packed output `noise_pred_dq [1,1024,64]` is unpacked back to
NHWC `(1, 64, 64, 16)` before being fed to the scheduler.

#### 6. VAE decode
After the loop, latents are un-scaled:
```python
vae_input = (latent_in / 1.5305) + 0.0609
```
The VAE decoder session (`sample_dq -> output_sample_dq`) returns raw float32 output which is
clipped and scaled to `uint8 [512, 512, 3]`.

#### 7. Output
The RGB array is saved as a PNG to
`C:\Users\HCKTest\.openclaw\workspace\Output\images\sd3_npu_output_<timestamp>.png`.

Per-model timing is printed at the end — call count, total ms, and average ms per session
(`text_encoder`, `text_encoder_2`, `transformer`, `vae`).

### Session client architecture

`SD3_Tool.py` never creates an `ort.InferenceSession` directly. Instead:

1. `_get_store()` connects (lazily, once per process) to `session_server.py` via
   `multiprocessing.managers` on `127.0.0.1:50001`.
2. `get_session(name)` returns a `_ServerSession` wrapper that forwards `.run()` and
   `.get_inputs()` calls to the server over IPC.
3. The server runs inference on its pre-loaded sessions and returns numpy arrays back to the
   client.

This means the QNN model load time is paid once at server startup, not on every `SD3_Tool.py`
invocation.

## Session server details

The server (`session_server.py`) avoids the cold-start penalty of loading ONNX QNN context
binaries on every run. All four models are loaded once at startup and held in memory. Client
processes connect via `multiprocessing.managers` (TCP, `127.0.0.1:50001`, auth key
`sd3-ort-server`) and call `run_session(name, feeds)` — no ONNX session is ever created in the
client.

QNN HTP provider settings used by the server:

| Option | Value |
|---|---|
| Backend | `QnnHtp.dll` (from the QAIRT SDK at `QAIRT_SDK_ROOT`, not the pip-bundled one) |
| Performance mode | burst |
| Graph optimization | level 3 |
| VTCM | 8 MB |

`htp_arch` is intentionally left unset — the onnxruntime version here doesn't parse newer
architecture strings (e.g. this device's actual v81) and just ignores an incorrect value with a
warning; the real architecture is read from the context binary itself regardless.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Unsupported model IR version: 13, max supported IR version: 10` | `onnx` package defaults to a newer IR version than `onnxruntime-qnn` supports | Already fixed in `gen_qnn_ctx_onnx_model.py` (pins `ir_version=10`) — re-run `bin_to_onnx.py` if you see this |
| `Opset 26 is under development` / opset errors | Same root cause, opset instead of IR version | Already fixed (pins opset 22 / com.microsoft 1) |
| `QNN_CONTEXT_ERROR_INVALID_ARGUMENT` (error 5000) loading a model | `QnnHtp.dll` version mismatch — the pip-bundled DLL is older than the SDK the binaries were built with | `session_server.py` points `backend_path` at the matching QAIRT SDK's `QnnHtp.dll`; verify `QAIRT_SDK_ROOT` is set correctly |
| `TypeError: '<' not supported between instances of 'NoneType' and 'NoneType'` in `gen_qnn_ctx_onnx_model.py` | Original script never copied tensor `id` from the extracted JSON | Already fixed in `parse_qnn_graph()` |
| `OSError: [WinError 10048] Only one usage of each socket address...` | A previous `session_server.py` instance is still running and holding port 50001 | Find and stop it: `Get-NetTCPConnection -LocalPort 50001`, then `Stop-Process -Id <pid> -Force` |
| SSL cert errors downloading tokenizers from HuggingFace Hub | Network/proxy cert issue on this machine | `SD3_Tool.py` loads tokenizers from the already-cached `stabilityai/stable-diffusion-3.5-medium` snapshot instead of the standalone repos — works fully offline if that repo is cached |
